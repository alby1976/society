# Public Document Export Policy

## 1. Purpose

This policy establishes how documents may be selected, reviewed, exported, and published publicly.

The Society should not publish internal governance, legal, personnel, safeguarding, financial, resident, donor, or board-confidential material without proper review.

---

# 2. Governing Principle

Public release requires approval.

A document being well-written does not make it public. A document being generated does not make it public. A document being shared internally does not make it public.

---

# 3. Public Release Review

Before public release, confirm:

- document is approved for public audience;
- confidentiality level permits public release;
- legal review completed if needed;
- theological review completed if needed;
- board approval completed if needed;
- personal information removed;
- donor information removed unless approved;
- resident or vulnerable person information removed;
- public status language accurate;
- chapter recognition language accurate;
- donation language accurate.

---

# 4. Documents Usually Suitable for Public Review

Documents that may be candidates for public release after approval:

- mission statement;
- vision statement;
- core values;
- statement of faith;
- public annual report;
- public ministry overview;
- public contact page;
- public donation policy summary;
- public safeguarding statement;
- public privacy statement.

---

# 5. Documents Usually Not Public by Default

Documents not public by default:

- board minutes;
- internal risk registers;
- legal issue registers;
- safeguarding reports;
- incident reports;
- donor records;
- grant applicant records;
- personnel policies with sensitive detail;
- housing resident records;
- confidential chaplaincy documents;
- internal decision registers;
- legal advice;
- internal audit records;
- draft policies not approved for release.

---

# 6. Public Export Label

Public export files should include a label such as:

```text
Public Release Candidate
```

or:

```text
Approved Public Version
```

Do not use `Approved Public Version` unless approval has actually occurred.

---

# 7. Public Export Record

Each public export should record:

- document title;
- version;
- release date;
- approving authority;
- public location;
- source file;
- review completed;
- expiry or review date.

---

# 8. Website Publication

Website publication must follow [[Website and Digital Presence Policy]].

Public files should be posted only by authorized persons.

---

# 9. Corrections

If a public document is wrong, outdated, or improperly published, the Society should correct or remove it promptly.

Correction should be recorded.

---

# 10. Review

This policy should be reviewed annually and after any major public release or public communication issue.
