# Missing Link and Dependency Review Checklist

## 1. Purpose

This checklist helps review Obsidian wiki-links, dependencies, related documents, and cross-document references before release.

Broken links increase mental load and make the vault harder to trust.

---

# 2. Link Review Rules

1. Every core dashboard link should resolve.
2. Every registered document should exist in `source/`.
3. Every dependency should point to a real or intentionally planned document.
4. Missing documents should be listed rather than ignored.
5. Duplicate titles should be resolved or documented.
6. Renamed documents should update inbound links.
7. Generated outputs should not be edited to fix links; source files should be corrected.

# 7. Dependency Integrity Review

For each document, check:

- `dependencies` are real documents;
- `related-documents` are real or intentionally planned;
- `supersedes` is accurate;
- dashboard links are current;
- registry references use correct title;
- document title matches filename where practical.
